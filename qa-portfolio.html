🐛 Bug Reports

Bug #1: Password Field Shows Plain Text

CRITICAL

📍 Steps to Reproduce:

1. Navigate to login form 2. Click on password field 3. Type any password 4. Observe the text displayed

🎯 Expected Result:

Password should be masked with dots (•••••) or asterisks (*****) for security

✅ Expected:

Password field shows: •••••

❌ Actual:

Password field shows: password123

💡 Impact:

Security vulnerability. Anyone looking at the screen can see the user's password. This violates basic security practices.

Bug #2: No Email Format Validation

CRITICAL

📍 Steps to Reproduce:

1. Navigate to login form 2. Enter "invalidemailaddress" (no @ symbol) 3. Enter any password 4. Click Login 5. Form accepts invalid email

🎯 Expected Result:

Form should reject email without @ symbol and display error: "Please enter a valid email address"

✅ Expected:

Error message displays: "Invalid email format"

❌ Actual:

Form accepts "test" as valid email

💡 Impact:

Users can submit invalid emails. Backend will likely reject it, causing poor user experience.

Bug #3: No Button Disable to Prevent Double Submission

HIGH

📍 Steps to Reproduce:

1. Navigate to login form 2. Enter valid email and password 3. Click Login button multiple times rapidly 4. Observe button does not disable

🎯 Expected Result:

Login button should disable immediately after first click to prevent double submission

✅ Expected:

Button disables and shows "Processing..." after click

❌ Actual:

Button remains enabled and clickable multiple times

💡 Impact:

User could accidentally submit form multiple times, potentially creating duplicate accounts or transactions.

Bug #4: Form Does Not Clear After Successful Login

HIGH

📍 Steps to Reproduce:

1. Navigate to login form 2. Enter valid email and password 3. Click Login 4. Click Login again without clearing fields 5. Success message appears again

🎯 Expected Result:

After successful login, form should clear and either redirect to dashboard or show fresh form

✅ Expected:

Form fields clear, redirect to dashboard, or form resets

❌ Actual:

Form fields retain values, user can submit again immediately

💡 Impact:

Confusing user experience. Not clear if login was successful or if user needs to try again.

Bug #5: Weak Password Validation (Minimum 3 Characters)

HIGH

📍 Steps to Reproduce:

1. Navigate to login form 2. Enter email: test@test.com 3. Enter password: "abc" (3 characters) 4. Click Login 5. Form accepts weak password

🎯 Expected Result:

Password minimum should be 8+ characters. Should show error: "Password must be at least 8 characters"

✅ Expected:

Error: "Password must contain 8+ characters"

❌ Actual:

Accepts 3-character password without warning

💡 Impact:

Security risk. Very weak passwords are accepted, making accounts vulnerable to brute force attacks.

Bug #6: Missing "Forgot Password" Link

MEDIUM

📍 Steps to Reproduce:

1. Navigate to login form 2. Look for "Forgot Password?" link 3. Link is not present on the form

🎯 Expected Result:

"Forgot Password?" link should be displayed below password field

✅ Expected:

Link displays: "Forgot Password?"

❌ Actual:

Link is missing from form

💡 Impact:

Users who forget their password have no way to reset it. Leads to account lockouts and poor UX.

Bug #7: Error Messages Are Vague

MEDIUM

📍 Steps to Reproduce:

1. Navigate to login form 2. Leave email blank 3. Click Login 4. Error message shows "Invalid email"

🎯 Expected Result:

Error message should be more specific: "Email field is required" or "Please enter a valid email address"

✅ Expected:

Error: "Email field is required"

❌ Actual:

Error: "Invalid email"

💡 Impact:

Users don't know what went wrong or how to fix it, leading to frustration and abandoned logins.
